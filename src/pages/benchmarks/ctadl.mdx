# CTADL taint analysis

<p className="bench-lede">
How fast <FL/> runs the taint analyses of <a href="https://github.com/sandialabs/ctadl">CTADL</a>, compared with Soufflé.
</p>

<dl className="spec">
  <dt>Engines</dt>
  <dd><FL/> (with string interning) vs Soufflé 2.5 as CTADL's Datalog engine, via <a href="https://github.com/flowlog-rs/ctadl-flowlog">ctadl-flowlog</a>. Each analysis is compiled once and cached, so times exclude compiling.</dd>
  <dt>Workload</dt>
  <dd>29 programs, each indexed (<code>ctadl index</code>) then queried for taint flows (<code>ctadl query</code>): 14 Ubuntu 22.04 executables through Ghidra's P-code, 13 F-Droid Android apps through JADX, and 2 synthetic programs.</dd>
  <dt>Measured</dt>
  <dd>Run time of each whole <code>ctadl</code> command and of the analysis binary alone, and peak memory (RSS), median of 3 runs after a warm-up.</dd>
  <dt>Results</dt>
  <dd>The SARIF reports have the same taint results on all 27 programs that have them. The databases differ only where CTADL's choice-domain relations let each engine keep another valid witness, and in what CTADL derives from those witnesses.</dd>
  <dt>Platform</dt>
  <dd>AMD EPYC 7V13 (Milan), 24 cores, 216 GiB RAM, Linux 6.8. Both engines run at 16 threads.</dd>
</dl>
